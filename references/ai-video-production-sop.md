# AI 短片自动生产 SOP

## 0. 交付铁律

1. 低成本不等于低质量。只缩小制作规模，不降低创意、镜头、商品真实性、声音、节奏和验收标准；成本不够时调整路线或报告缺口，不得退化成模板化图文快剪。
2. 视频制作任务必须先交付并验收真正的视频。静态卡片、分镜、提示词、图片推拉、幻灯片或工程文件不算最终成片；FFmpeg 只承担剪辑、转场、字幕、混音、编码和质检，不能代替视频镜头生产。
3. 每条视频验收通过后，必须继续交付同一商品的 5 张小红书图文，默认依次为封面 Hook、场景/痛点、核心卖点、细节/证据、总结/CTA。图片模型只生成无字视觉，中文、字母、数字、价格、品牌和 CTA 全部确定性后期渲染。
4. 成本清单必须同时覆盖视频和 5 张图文。默认价格按图片 0.25 元/张、视频 0.2 元/秒计算，并单列首次生成、预留重试和总上限。

## 1. 启动条件

- 先锁定受众、地域、平台、时长、商品事实和不可虚构项。
- 最终成片必须在 15–120 秒之间，单个分镜、镜头和生成单元可短于 15 秒；禁止无内容框架的硬广展示，人物故事、趣味内容、视觉观赏和感官内容等所有路线都先通过 `screenwriting-master` 的分阶段编剧流程。
- 先披露首次生成成本。用户明确选择创意路线后，自动生产首次成片。
- 只有超出已披露成本、改变路线、新增外部权限或追加付费重试时暂停询问。
- 生成前按 `script-direction.md` 确定观看承诺、节拍、商品角色和实际动作时长；先完成脚本/临时声音预演。多轮脚本升级不自动授权多轮付费生成。

## 2. 模型路由与接口

- 不再隐式替用户选择模型。项目必须显式记录 `model`：`MiniMax-H3` 或 `Seedance-2.0`。
- `MiniMax-H3` 使用 `h3-prompt-writing`：按 T2VA/I2VA/FL2VA/L2VA/Ref2VA 选择模式，使用 H3 结构化字段和引用标签；H3 v2 首尾帧图片必须明确为 `first_frame` 或 `last_frame`。
- `Seedance-2.0` 使用 `seedance-prompt-zh`：使用 `@图片/@视频/@音频` 引用职责和分时段动作结构。
- 使用 `replication/tools/generate-video.sh`；provider 必须与项目模型一致：H3 对应 `minimax`，Seedance 对应 `seedance`，禁止只改 provider 而不重写提示词。
- MiniMax H3 v2 的图片必须明确标为 `first_frame` 或 `last_frame`，不得把模糊的 `reference_image` 直接传入。
- 轮询必须识别 `completed / success / succeeded` 与失败、取消状态，并在完成后下载 MP4。

## 3. 单商品图低成本方案

先按叙事切点拆生成单元；首尾帧不应把本该硬切的场景强行变成连续变形。当故事确实适合一个连续主动作、最后落到商品且只有一张商品图时，可采用：

```text
1 张无文字叙事首帧
+ 10-12 秒 H3 首尾帧视频
+ 3-5 秒真实商品图后期落版
```

- 首帧负责人物、地域、场景和情绪；尾帧使用原商品图裁切或无损排版，锁定包型、颜色、logo 与细节。
- H3 中段只承担一个主要动作和一次状态变化，不要求模型同时完成复杂表演、准确文字与商品结构证明。
- 真实商品图必须在最终成片中停留至少 2 秒；模型生成的商品只能承担过渡，不承担最终购买证据。

## 4. 文字与声音

- 生成提示词要求无可读文字并保留字幕安全区。
- 中文、英文字母、数字、价格、品牌名、CTA 和免责声明全部后期渲染。
- 当 FFmpeg 没有 `drawtext` 时，先用系统字体渲染透明 PNG，再叠加；所有无限循环字幕输入必须用 `overlay=shortest=1` 随主体段结束，避免吞掉后续片尾。
- 本机可用剪映专业版时，最终剪辑、免费文本朗读、混音和导出均在剪映完成；先导入无配音画面，再生成旁白，避免把临时配音混入终版。
- 配音必须选择剪映内不带钻石、VIP 或会员标识的免费音色。根据受众和情境选择音色，不凭名称假定免费；在生产日志中记录音色名称、免费状态、语速和实际朗读时长。
- 禁止把 macOS `say`、操作系统语音或其他临时 TTS 用作最终旁白；它们只能用于付费生成前的节奏预演，且预演音频不得进入交付文件。
- 有旁白时先在剪映生成并测量实际时长，再定稿；超时时精简文案，短于片长时不为填满而补话。按节拍安排对白、环境声、拟音与留白，不要求旁白覆盖主要叙事；禁止极端调速硬塞。
- 文本朗读生成独立音频后，删除或隐藏仅用于朗读的临时文本层，避免与确定性字幕重复。
- 混音后检查最大电平、平均电平、声道、采样率和完整解码。

### 剪映终剪最小流程

1. 导入无系统配音的画面母版，确认画幅、帧率和时长。
2. 脚本需要旁白时，添加定稿文本，选择剪映免费音色并生成文本朗读；无旁白路线直接安排实际需要的声音。
3. 实听首尾和转折点，按实际时长微调文案、停顿和语速。
4. 保留独立朗读音频，删除朗读临时文本层；字幕、品牌与 CTA 使用确定性后期层。
5. 在剪映完成音乐压低、峰值检查与最终导出，并记录工程名称和导出文件。

## 5. 验收

### 5.0 生成前语义闸门（低成本优先）

分镜阶段即执行检查：节拍覆盖、动作归属、起止状态、删除损失和前后衔接必须写入镜头契约与 slots.json；提示词只是把已确认契约转成模型指令，不能补救缺失的故事分析。

视频生成不是第一次剧情验证。任何付费视频请求前，必须保存逐节拍对照表：原故事不可丢失的动作/信息、承载镜头或声音、对应首帧/尾帧/参考图及图片确认结论。每个生成单元只能承担表中声明的主要动作；若图片无法证明人物身份、空间关系、道具位置或动作起止状态，标记 generation_allowed=false，先修订分镜或图片，不得“先生成看看”。

图片通过后锁定视频提示词、引用和模式；视频阶段不得临时补写对白、增加动作或改变空间。提示词 skill 审查证明可执行，但不替代故事节拍分析。视频生成后的检查以技术 QC 和明显执行偏差记录为主；语义重做只针对最小失败单元并单独披露成本。

先完整播放与听审，按 `script-direction.md` 检查观看承诺是否兑现、人物行为是否可读、声音与停顿是否服务节拍、商品是否参与关键体验。再至少截取开场、动作转折、状态完成和商品片尾四帧检查技术项；抽帧不能代替时序与声音验收。无法播放或听审时注明未验收部分。

- 人物年龄、身份和前后脸部一致。
- 地域、服饰和礼俗没有跑偏。
- 手指、衣料、道具和商品没有明显穿模。
- 中文、品牌与 CTA 清晰且处于安全区。
- 商品片尾来自真实素材，不是模型重绘。
- 成片时长、分辨率、帧率、音频和编码符合平台要求。
- 终版确由剪映导出；有生成旁白时确为已记录的剪映免费音色，且不存在系统 TTS 音轨。无旁白路线不因此判失败。
- 主要镜头具有真实时间变化、动作或场景演进，不是仅靠静态图片缩放制造的伪视频。

### 小红书 5 张图文验收

- 视频已经先完成并通过验收，图文与视频使用同一创意母题、商品事实、色彩和受众语气。
- 恰好交付 5 张独立成图，默认使用小红书友好的 3:4 竖版；所有文字清晰、无模型乱码并处于安全区。
- 五张分别承担封面 Hook、场景/痛点、核心卖点、细节/证据、总结/CTA，不做五张近似封面。
- 商品外观、颜色、结构、价格和声明与证据一致；AI 场景不能冒充真实评价或虚构功效。
- 逐张检查尺寸、文字、裁切和可读性，并输出可直接发布的 PNG/JPG。

## 6. 迭代与成本记录

- 记录输入素材、提示词、模型、生成秒数、图片张数、单价、响应、下载文件、剪映工程、免费音色名称、语速、朗读时长、视频验收和 5 张图文验收结论。
- 首版失败时先判断问题属于创意、首帧、视频动作、商品一致性、文字还是后期。
- 只重做最小失败单元：字幕问题只重导后期；商品尾帧问题只重做真实落版；单段动作问题只重生成该段。
- 追加付费重试前展示首版问题、修正变量、增量成本和累计成本。

## 7. 无人值守一级编排闸门

无人值守任务必须在第一次付费请求前写出项目目录内的 `automation/preflight.json`、`automation/preflight.md` 和 `automation/cost-plan.json`。闸门顺序固定为：

```text
输入与 git 盘点 → 只读技术/视觉预检 → 首次成本与最坏成本
→ Seedance 可实现性审查与优化 → 凭据/接口/引用规则检查 → 付费闸门 → 生成 → 下载与逐文件验收
```

预检至少记录每个镜头的已有资产、缺口、输入 hash、引用职责、预计秒数、人物/服装/场景连续性、动作归属与可拍性、提示词时间容量、运镜冲突、前后衔接、文字/水印禁令，以及模型的 `first_frame`、`last_frame`、`reference_*` 兼容性。任一项为 `fail`、`unknown` 或需要依赖未验收素材时，该镜头的 `generation_allowed` 必须为 `false`；不能用“先生成看看”绕过闸门。

任何视频提示词在输出为正式版本、展示为生产资源或进入付费提交前，必须先使用 `seedance-prompt-zh` 做一次可实现性审查，并依次回答：当前参考素材与时长能否让模型容易、稳定地表现目标画面；哪些动作、物体连续性、人物交互、运镜或声音要求不容易；如何在不改变主题和叙事功能的前提下降低难度；优化后的最终提示词是否达到可执行标准。审查必须优先减少同段主要动作、消除物体数量与动作归属歧义、让首帧包含动作起点和终点、用固定构图或焦点转移替代不必要的多次换景，并把对白、字幕、精确声桥和淡黑留给后期。

审查记录必须与最终提示词同存，并包含 `skill=seedance-prompt-zh`、`result=pass`、`renderability=easy|acceptable_after_optimization`、非空 `difficulties`、非空 `optimizations_applied`、空 `unresolved_blockers` 和最终 `.prompt` 文本的 `reviewed_prompt_sha256`。提示词修改后 hash 失配即审查失效；未通过、记录缺失或仍有 blocker 时，不得称为“正式提示词”、不得出现在生产资源页、不得调用任何视频生成接口。

预算算法使用实际新增资产计费：

```text
首次成本 = 新首帧张数 × 0.25 + 新视频秒数 × 0.20
最坏累计 = 首次成本 + 已披露的重试预留
```

已有素材不计费，但必须技术和视觉验收。重试预留不能把最坏累计推过硬上限 20 元；每次请求前重新计算剩余余额。首次失败只做诊断并标出最小失败单元，付费重试不得自动执行，必须先在报告中列出增量成本并等待新的授权。预算低于 10 元时不为凑目标增加无关生成，按必要镜头的实际成本执行。

镜头验收分为技术和视觉两道：`ffprobe` 核对路径、时长、分辨率、帧率、编解码和音频；`ffmpeg` 完整解码；抽取首帧、动作转折、状态完成和尾帧；再由可用的视觉检查工具确认主体、动作因果、连续性、穿模、文字/水印和真实时间变化。无法完成视觉检查只能标记 `not_accepted`，不能声称通过。静态推拉、幻灯片或分镜图永远不能替代真实镜头。

## 8. 统一编排器接口

未来统一编排器以以下接口交换数据，项目目录只保存实例化记录：

| 接口 | 必需字段 |
|---|---|
| 输入 | `project_id`、`route`、脚本/故事板版本、镜头任务、素材路径与 sha256、模型/provider、预算上限、平台规格、禁用项 |
| 状态 | `preflight`、`cost_planned`、`gate_blocked`/`gate_open`、`first_frames`、`videos`、`download_qc`、`editing_pack`、`human_edit_pending`、`complete`；每个状态带依赖、时间、失败类型和重试授权 |
| 产物 | 请求 JSON、响应 JSON、下载文件、ffprobe/解码/抽帧证据、成本明细、提示词版本、剪辑交接包、QC 报告、最终报告 |

状态只能向前推进；闸门失败时允许生成报告和剪辑草案，不允许偷偷执行下游付费阶段。所有产物必须可由 `manifest.json` 通过路径、hash、模型、时长、成本和验收结论反查。

## 9.1 事务化付费资产闸门（实施版）

`replication/tools/paid-asset-orchestrator.sh` 将 `automation/orchestrator-state.json` 作为唯一事实源，使用 `flock` 和原子替换写入。每个付费资产只能经历 `ready → submitting → generated_pending_qc → accepted/rejected`；`submitting`、`ambiguous_submission` 和 `generated_pending_qc` 任一存在时，全局付费闸门关闭。提交前创建不可覆盖的 `submission.locked`，永久保存提示词、请求体、响应、生命周期和 SHA-256；curl 中断按可能已计费处理，禁止自动重提。状态迁移必须先记账再开放下一个依赖资产。

本集迁移文件为 `replication/output/love-story-level-5/automation/orchestrator-state.json`，旧 `manifest.json` 仅作为迁移前记录；后续由状态快照派生。

## Seedance 提示词统一作者与校验门禁

图片和视频的最终生产提示词只能由 `seedance-prompt-zh` 生成。所有生成入口在 POST 前必须用 `validate-seedance-prompt-review.sh` 验证 `seedance_prompt_review` 的作者声明、资产类型、检查项、阻塞项和最终提示词 SHA-256。任何缺失、类型不符、存在 blocker 或 hash 失配均在本地停止。历史生成记录不得事后补签为“生成前通过”；修改提示词必须重新调用该 Skill。

### 页面确认即锁定

当用户在审阅页面查看后直接要求生成图片或视频，该指令表示页面当前提示词已确认。生成流程必须对页面所示文本原样执行 `seedance-prompt-zh` 校验并绑定 SHA-256；不得重新生成、润色或替换提示词。校验失败时停止并报告，只有用户确认页面更新后的新文本才能继续。

确认语义：用户明确说“开始生成首尾帧”“开始生成图片”“开始生图”或其他明确生图命令，即确认生图前的待确认步骤；用户明确说“开始生成视频”或“开始生视频”，即确认视频前的待确认步骤。不要重复追问同一层级确认。预算、依赖、生成前门禁、禁止覆盖和生成后技术/语义验收仍然必须执行。

分镜视频不得默认套用首尾帧模式。ads_skill 必须根据原始故事和分镜动作链判断 I2VA、FL2VA 或参考图生视频：动作自然向后发展且无严格收尾用 I2VA；需要固定起止状态或连续转场用 FL2VA；只需人物/场景/风格一致用参考图。模式和判断理由写入 slots.json。

状态规则：视频生成文件成功落盘且技术 QC 通过后，当前分镜即标记为“通过（生成完成）”，不等待额外语义确认。只有用户提出后续修改、重做或验收问题时，才将状态改为待处理或修订；底层 semantic_qc 字段仍保留真实状态。
