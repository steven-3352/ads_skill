# 项目级故事广告生产 SOP

本 SOP 适用于从用户主题/故事到可手工执行的图片、视频项目。项目以契约为唯一事实源，HTML 只负责展示契约当前状态。

## 1. 对话与信息收集

用户输入主题或故事后，ads_skill 不立即生成素材。通过多轮对话补全受众、平台、时长、地域、人物关系、情绪目标、真实素材、预算、禁用项和用户希望保留的故事细节。每轮区分“用户事实 / 合理假设 / 待确认问题”，直到故事目标和制作边界足够明确。

## 2. 剧本、分镜与契约

screenwriting-master 完善剧本和不可丢失的故事节拍；ads_skill 将节拍转成可执行分镜。拆镜头时同步写明人物、道具、背景、动作起点→过程→终点、声音、转场、删除损失和图片可验证证据。复杂动作才拆分，连续且可控制的动作保持一个分镜。

人物、道具、背景、公共资产、每个分镜及每个提示词槽位都必须有契约文件（推荐 JSON）。契约记录状态、路径、hash、来源、依赖、模型、提示词作者与校验结果；没有内容的槽位保留并标记为空，不删除字段。

## 3. HTML 模板

每个项目生成统一 HTML：主页展示原故事、剧本版本、节拍表、公共基础资产表、项目状态和分镜导航；每个分镜页只展示当前分镜相关的故事原文、节拍映射、动作契约、引用资源、首帧/尾帧/参考图、视频、提示词槽位和执行状态。页面不扫描历史目录，所有内容从当前契约读取；不存在的资产或提示词显示“空”。废弃页面必须从导航和发布目录移除。

## 4. 手工执行脚本

项目目录必须包含 `EXECUTION.md`（或同义的执行脚本 Markdown）。文件按依赖顺序列出每个资产的可复制命令：生成首帧、尾帧、参考图、视频以及技术 QC。每条命令标注输入契约、输出路径、预计成本、前置条件和执行后需要更新的契约字段。命令不得隐式改写提示词。

执行完成后，人工或脚本必须更新对应契约（路径、hash、状态、响应、QC、成本和时间），再刷新/重新打开 HTML；HTML 显示的永远是契约最终状态，而不是目录中残留文件。

## 5. 提示词与生成闸门

图片和视频提示词统一放在 `prompts/`，只能由当前模型对应的提示词 Skill 生成并校验。图片证据通过后才解锁视频；用户明确生成命令视为确认当前页面内容，但仍执行本地校验、预算、依赖和防重复提交检查。视频阶段原样执行已确认提示词，不临时补写剧情。

## 6. 状态与追溯

状态只能按依赖向前推进：`draft → contract_ready → image_pending/accepted → video_pending/generated → technical_qc → complete`。每个状态变更写入日志，资产不可覆盖；失败只标记最小失败单元。任何人都能通过契约反查提示词、输入、命令、输出、hash、成本和页面展示结果。
