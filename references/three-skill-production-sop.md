# 三 Skill 协作生产 SOP

本 SOP 规定 `ad-creative-expert`、`screenwriting-master` 与模型提示词 Skill 的分工、分流和交接。`ad-creative-expert` 始终是商业总控；所有视频都必须先由 `screenwriting-master` 建立内容框架，编剧既负责人物故事，也负责趣味规则、视觉观赏、幽默与感官内容的概念、推进和兑现。禁止无内容框架的硬广展示。

## 1. 路由判断

在创意路线阶段判断内容驱动与复杂度，但不能取消编剧环节：

创意先并列评估两条母路线：A 线“创意/品牌观赏”用炫酷、好玩、视觉规则、幽默、奇观或感官过程创造观看奖励和品牌印象；B 线“日常/问题解决”用用户情绪、关系中的真实摩擦和具体问题解决创造共情与实用价值。两线没有固定先后顺序，按商品属性、受众、传播目标、事实证据和制作条件推荐预期效果更好的一条；混合时必须明确主次。冲突不要求激烈，不得用争吵、羞辱、卖惨或虚假焦虑代替内容。

| 路线 | 判断信号 | 调用链 |
|---|---|---|
| 对话/生活内容 | 两人关系、一次选择、误会、反应或生活动作形成内容闭环 | ads → screenwriting → ads → 模型提示词 Skill → ads |
| 趣味/幽默内容 | 一个好玩的规则、预期偏离或观察持续升级并回扣商品 | ads → screenwriting → ads → 模型提示词 Skill → ads |
| 视觉/感官内容 | 变形、尺度、节奏、材质、声音或过程本身形成观赏性和完成感 | ads → screenwriting → ads → 模型提示词 Skill → ads |
| 情感/品牌故事 | 依靠人物目标、关系、选择、潜台词、情绪转折或反转成立 | ads → screenwriting → ads → 模型提示词 Skill → ads |

**最终成片**必须在 15–120 秒之间；单个分镜、镜头和模型生成单元可以根据动作需要短于 15 秒。15 秒可以采用微故事，也可以采用趣味规则、视觉奇观、幽默观察或感官过程；最低要求是形成“观看入口 → 可感知推进 → 具体兑现 → 商品参与”的可拍内容闭环。把产品卖点分给两个角色轮流念不算内容。所有路线都必须经过 `screenwriting-master`，短时长只缩小内容规模，不跳过编剧流程。

## 2. 沟通闸门

### 第 1 轮：锁定任务

由 ads Skill 询问或合理假设：产品事实、购买者/使用者/观看者、平台、地域、目标、时长、素材、证据、限制和预算。输出 Brief 诊断，不生成付费素材。

### 第 2 轮：确定表现形式

先扫描 `references/cases/`、样本蒸馏、创意迁移文档和历史项目，分别寻找适合 A/B 两线的可迁移机制；只继承观看机制、内容结构和制作经验，不复制表面资产。随后至少比较三条机制不同的路线，并对每条标注：

- 所属母路线：A 创意/品牌观赏；B 日常/问题解决；或有明确主次的混合
- 项目案例来源、继承机制、新商品接口和拒绝/采用理由
- 内容形式：对话/生活 / 趣味幽默 / 视觉感官 / 情感故事
- 首 1–3 秒 Hook
- 产品事实与动作
- A 线的观赏奖励与品牌印象，或 B 线的用户情绪、关系冲突与待解决问题
- 为什么适合当前商品和受众，预期效果依据是什么
- 内容如何推进和兑现；需要人物时补人物/动作关系
- 在 15–120 秒最终成片时长内是否能闭合
- 生成模型难点、成本和风险

让用户选择路线或混合路线。用户选择后，路线类型即锁定；除非改变路线、超出已披露成本或需要新权限，不再反复确认。

### 第 3 轮：按路由执行

- 所有广告：`screenwriting-master` 先输出概念/核心动作、观看入口、推进、兑现和可摄影视听脚本；人物故事再补人物、目标、关系与变化。ads 随后转成广告镜头任务单。
- 长内容：screenwriting 完成相应格式的阶段产物，ads 负责商业接口和平台切条。

### 第 4 轮：前置验证、生成与验收

Seedance 每次只解决一个镜头难题，单段通常 4–15 秒。ads 负责真实商品素材、字幕/CTA 后期、剪辑、声音、视频验收和 5 张小红书图文。
付费视频生成前，ads 必须完成“原始内容节拍→镜头动作/变化→图片证据”的低成本验证：每个不可丢失的人物动作、规则升级、视觉变化、笑点或感官兑现都绑定具体画面或后期声音；先确认首帧/尾帧或参考图中的主体、空间、道具、状态、动作或变化起止及前后衔接。图片未通过不得提交视频；图片通过后按已确认提示词原样执行，不在视频阶段重新解释内容。视频完成后的语义检查仅用于记录模型偏差和决定最小重试，不能替代生成前方案验证。

## 2.5 分镜内置验证（先于提示词）

分镜拆分时必须同步完成内容节拍映射，不得先写“好看的画面”再事后解释内容。每个镜头任务必须明确：承载的原始内容节拍、人物/物件/规则/感官变化的主体、起点→过程→终点、观众从上一镜头已知什么、本镜头新增什么、不可删除的信息、前后镜头的空间/道具/视线/声音衔接，以及图片阶段可验证的证据。若一个镜头承载多个主要变化，或无法用首帧/尾帧/参考图证明推进与兑现，应在此阶段拆分或改写；未完成映射的镜头不得交给提示词 Skill。
## 3. 交接字段

### ads → screenwriting

```text
产品事实 / 受众 / 平台 / 传播主张 / 必须出现的产品动作 /
必须保留的证据 / 时长 / 禁用表达 / 期望情绪 / CTA
```

### ads → Seedance

```text
镜头编号 / 时长 / 叙事功能 / 首帧 / 尾帧 / 主体 / 场景 /
动作 / 运镜 / 景别 / 声音 / 必须保持 / 禁止出现 / 前后镜头衔接
```

Seedance 提示词必须明确每个 `@图片`、`@视频`、`@音频` 的职责，分时段描述动作，避免指令冲突；品牌、中文、价格、数字和 CTA 默认由后期渲染。

在交付最终提示词前，必须先由 `seedance-prompt-zh` 审查“能否容易、稳定表现”，列出不容易实现的部分，在不改变主题和镜头叙事功能的前提下优化，再对最终版本复审。未通过复审的内容只能叫草稿，不能进入生产页面或生成接口。

### 模型提示词技能 → ads

`Seedance-2.0` 使用 `seedance-prompt-zh`，返回 `@` 引用提示词；`MiniMax-H3` 使用 `h3-prompt-writing`，返回对应 T2VA/I2VA/FL2VA/L2VA/Ref2VA 结构。两者都必须返回最终提示词、素材引用表、生成参数、风险、需要后期修正的内容和是否可进入剪辑。失败只重做最小失败镜头，并记录增量成本。

## 4. 15 秒内容广告参考骨架

```text
0–2 秒：可辨认的处境、问题、规则、奇观或感官入口
2–6 秒：内容开始推进，建立期待、关系或可观察变化
6–11 秒：商品参与关键动作，规则、感受、关系或状态发生升级
11–13.5 秒：兑现观看承诺，并给出真实产品证据
13.5–15 秒：内容回扣、商品/品牌和自然 CTA
```

这是最终成片的参考骨架，不得机械套用，也不得为了套结构增加无关剧情。最终成片不得短于 15 秒，但单个分镜、镜头或生成单元可以更短；每段视频生成只承担一个主要动作，最终商品证明使用原图或实拍。

## 5. 质量门

交给下一个 Skill 前，检查上游交付是否能回答：谁在看、为什么停留、产品做了什么、结果如何证明、下一步是什么。没有答案时退回 ads 创意阶段，不让 Seedance 用漂亮画面掩盖策略缺口。

视频完成后检查：动作因果、人物/商品一致性、文字安全区、真实商品证据、时长、音画和平台规格；通过后才制作恰好 5 张小红书图文。

## 6. 最小失败单元与人工剪辑交接

自动生产失败时先按责任边界归类：首帧构图或人物身份问题只重做对应首帧；单个动作、手部或时序问题只重做对应镜头；字幕、对白、旁白、混音和编码问题只回到后期。不得因一个镜头失败而隐式重生成整集，也不得把失败镜头降级成静态推拉。任何付费重试都要单独记录失败类型、修正变量、增量秒数/张数和累计成本，并等待新的授权。

交给人工剪辑的包必须逐镜包含：实际文件名和路径、文件状态（`accepted`/`not_accepted`/`missing`）、入点/出点与目标时长、硬切/叠化/声音桥、画面功能、连续性锚点、对白/旁白说话人及画内外状态、字幕安全区、拟音/环境/BGM 分轨和相对音量、导出规格、人工验收项。未通过视觉检查的素材可以列入“待替换”占位，但不得写成可直接发布的成片。

剪辑包还应明确最终人声由人工在剪映等后期工具完成：记录实际使用的免费非 VIP 音色、语速和朗读时长；不得使用系统 TTS 进入终版。没有商品广告时，明确写出“无品牌 CTA”，避免人工误加品牌落版。

## 7.1 统一编排器落地约束

统一编排器必须使用单一状态文件、资产级幂等 ID、不可覆盖输出、进程锁、原子状态写入和永久请求审计。生成顺序由 `depends_on` 决定；语义验收未记录 evidence、note、reviewer 前不得解锁下游。网络错误不等于未提交，任何 POST 后异常均进入 `ambiguous_submission`，等待人工查询供应商任务状态。

每个视频提示词必须携带可机器验证的 `seedance_feasibility_review`，并以 `reviewed_prompt_sha256` 绑定最终 `.prompt` 文本；缺失、未通过、存在未解决 blocker 或 hash 失配时，必须在本地关闭付费闸门，不能发起 POST。

## Seedance 提示词统一作者与校验门禁

图片和视频的最终生产提示词只能由 `seedance-prompt-zh` 生成。所有生成入口在 POST 前必须用 `validate-seedance-prompt-review.sh` 验证 `seedance_prompt_review` 的作者声明、资产类型、检查项、阻塞项和最终提示词 SHA-256。任何缺失、类型不符、存在 blocker 或 hash 失配均在本地停止。历史生成记录不得事后补签为“生成前通过”；修改提示词必须重新调用该 Skill。

### 页面确认即锁定

当用户在审阅页面查看后直接要求生成图片或视频，该指令表示页面当前提示词已确认。生成流程必须对页面所示文本原样执行 `seedance-prompt-zh` 校验并绑定 SHA-256；不得重新生成、润色或替换提示词。校验失败时停止并报告，只有用户确认页面更新后的新文本才能继续。

用户明确说“开始生成首尾帧”“开始生成图片”“开始生图”等生图命令时，视为已确认生图前待确认项；明确说“开始生成视频”“开始生视频”时，视为已确认视频前待确认项。无需重复形式化确认，但仍须执行提示词校验、预算与依赖门禁、不可覆盖检查及生成后验收。
