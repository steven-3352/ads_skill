# AI 视频制作总 SOP

本文件是新视频项目从初始化到逐镜视频验收的唯一生产流程，也是 Shot、Panel、Unit、公共资产、模型路由、提示词、付费生成和状态管理的唯一权威来源。其他文档可以补充策略、编剧、案例或模型知识，不得另建平行生产流程。

当前版本暂不决定最终成片的具体组接工具和创作方法，但在分镜阶段必须先记录后期任务、声音、字幕安全区、转场意图和导出目标，避免素材生成后才发现无法剪辑。最终成片方案未确认前，项目不得标记 `complete`。

## 1. 总原则与职责  〔🔴 P0 必牢记〕

### 1.1 不可覆盖原则

1. 原始故事、用户确认的创意概念或视听脚本是下游生产的唯一内容事实源。发现问题时上报，不得擅自加戏、删节拍或改味。
2. `ad-creative-expert` 是商业与生产总控；`screenwriting-master` 负责内容和剧本；H3/Seedance Skill 只负责把已确认的生成单元翻译成对应模型提示词。
3. 所有视频都要有观看入口、持续推进、具体兑现和商品参与，不得把卖点轮播、静态推拉或两人轮流念卖点当作内容。
4. 低预算只能减少人物、场地、镜头、生成次数和连续特效，不得降低创意、商品真实性、声音、节奏和验收标准。
5. 先完成低成本的故事、分镜、图片证据和提示词检查，再进行付费视频生成。不得用“先生成看看”代替设计。
6. 中文、字母、数字、价格、品牌、CTA 和免责声明默认由确定性后期完成；模型画面预留安全区，不承担准确文字。
7. 商品结构、参数、功效、医学过程、比较和评价必须有证据；AI 奇观不能冒充证明。
8. 每个失败只重做最小失败单元；任何新增付费重试必须披露增量与累计成本并重新获得授权。

### 1.2 Skill 职责链

```text
ad-creative-expert
  Brief、商品事实、受众、创意路线、模型/预算、生产总控
        |
        v
screenwriting-master
  核心动作、梗概、人物/规则、结构、节拍、可摄影视听脚本、自检
        |
        v
ad-creative-expert
  公共资产、视觉语法、Shot/Panel/Unit、后期任务、覆盖与成本
        |
        +--> h3-prompt-writing      MiniMax-H3 视频提示词
        |
        +--> seedance-prompt-zh     Seedance-2.0 视频提示词
        |
        v
ad-creative-expert
  生成编排、逐文件验收、状态、成本、页面与交付
```

### 1.3 图片提示词的当前边界

- `h3-prompt-writing` 只写 MiniMax-H3 视频提示词。
- `seedance-prompt-zh` 只写 Seedance-2.0 视频提示词。
- 在没有单独图片提示词 Skill 的情况下，由 `ad-creative-expert` 根据资产契约撰写公共资产图和关键帧图片提示词，并在契约中把 `promptAuthor` 记为 `ad-creative-expert`。
- 将来引入图片提示词 Skill 时，在项目 `prompt-policy.json` 中显式替换作者和校验器；不得把视频提示词 Skill 伪记为图片提示词作者。

### 3.1 目录规则

- 契约是唯一事实源；HTML 和 README 只展示契约状态，不能扫描目录猜状态。
- 公共资产只放 `assets/`；单镜资产只放当前 `shots/shot-SXX/`，不得引用其他镜头产物冒充公共资产。
- 提示词只放 `prompts/`，提示词文件保存作者、版本、最终文本和 hash。
- 生成文件不可覆盖；使用递增版本或资产 ID。废弃版本保留状态，不出现在当前导航。
- `final/` 只有完成技术、视觉、语义、声音和导出验收的成片。

## 4. 状态机与确认语义  〔🔴 P0 必牢记〕

### 4.1 项目阶段

```text
initialized
-> brief_pending -> brief_confirmed
-> route_pending -> route_confirmed
-> screenplay_pending -> screenplay_confirmed
-> production_plan_pending -> storyboard_confirmed
-> public_assets_pending -> public_assets_accepted
-> shot_images_pending -> shot_images_accepted
-> shot_videos_pending -> shot_videos_accepted
-> final_workflow_pending
-> final_qc
-> complete
```

状态只能按依赖向前推进；失败只退回最小责任单元。`shot_videos_accepted` 不等于完整成片，最终流程未定时停在 `final_workflow_pending`。

### 4.2 用户确认

- `screenwriting-master` 的每个编剧阶段结束后暂停，等待用户“通过 / 修改 / 自检”。
- 用户选中创意路线，只确认路线和已披露的首次生产预算，不等于确认未展示的剧本或提示词。
- 用户明确说“开始生成图片/首尾帧/生图”，表示当前页面的图片提示词和生图前内容已确认，不重复追问同一层级。
- 用户明确说“开始生成视频/生视频”，表示当前页面的视频提示词已确认，不重复追问同一层级。
- 确认不取消提示词、依赖、预算、防覆盖和技术/视觉验收。
- 页面确认后锁定当前提示词 hash；任何改字都会使确认和审查失效。

### 4.3 统一门禁与唯一编排入口 `run.sh`  〔🔴 P0 必牢记〕

正式生产的每一步只经仓库根 **`run.sh`** 推进——它是本状态机的唯一编排入口，取代一切平行入口（旧 `run-codex.sh` 等已归档 `deprecated/`）。它做三件事：① gate-in 校验前置状态；② 分发 `replication/tools/stages/stageN-*.sh` 做 run/gate-out 校验（收编所有校验器）；③ gate-out 通过后作为**总账唯一写者**原子 append 一条带哈希链的记录，推进主状态。

- **机器可读状态机**：`references/state-machine/main-sequence.json`（本 §4.1 序列的权威机读版，项目级共享；即 §3.1:181 画的 orchestrator-state 落点）。
- **三层账本**（各有唯一写者，交叉核验）：总账 `automation/<sub>.ledger.ndjson`（run.sh 写，append-only + 哈希链）｜付费子账本 `automation/<sub>.paid-state.json`（`paid-asset-orchestrator.sh` 写）｜audit 证据 `automation/<sub>.paid-state 的 requests/<id>/`（生成脚本写 lifecycle/sha256）。
- **项目描述符** `automation/<sub>.project.json`：`subproject_id/owner_globs/ledger/paid_state/model/state_sequence`。`owner_globs` 喂 foreign-guard 解决同目录多子片共存（他片零改动 gate）。
- **回合制半自动**：脚本做 gate-in + gate-out + 状态推进；智能内容仍由主会话派隔离子 agent 产出，但**不过 gate-out 不算数**。付费 stage（图/视频/TTS）委托 orchestrator，不重造。
- **底层生成脚本不动**：`generate-image/video/speech.sh` 保持可单独执行的原子工具，不塞账本/授权/状态。"唯一入口"落在**证据层**：绕过 run.sh 直调生成脚本的产物没有 paid-state 条目 + audit 证据链 + accept + 总账迁移，gate-out 不认、不进交付。
- **统一退出码**：0 推进成功｜2 用法/内部错误｜10 gate-in 拒（状态/证据不足，含状态不足拒付）｜11 回合制暂停（待子 agent 产出）｜12 gate-out 拒（产物缺/sha256 不符/validate 非 0）｜13 他片零改动 gate 失败｜20 付费委托失败｜30 哈希链断裂。
- **用法**：`run.sh <project-dir> <stage> --sub <sub> --phase <run|asset|qc|accept|reject|gate-qc|gate-out> [--unit <id>] [--evidence <file>]`；管理子命令 `--init --at <state>` / `--status` / `--history` / `--verify-chain`。stage 与相位绑定见状态机 JSON 的 `.stages`。

## 5. 阶段 0：初始化项目  〔🟡 P1 要内化〕

- 用户的视频任务、已有故事或商品资料。
- 当前仓库和环境中可用的 Skill、脚本与素材。

### 操作

1. 读取根 `SKILL.md` 和本 SOP。
2. 创建第 3 节目录、`README.md`、`CAPABILITY-MAP.md` 和空契约。
3. 盘点 Git 状态和已有文件；不覆盖、移动或删除来源不明的用户产物。
4. 按第 2 节记录强制能力和按需能力；相同规则冲突时，本 SOP 负责生产流程，专项参考负责其领域细节，用户最新指令最高。
5. 记录本次图片提示词作者、候选视频模型、生成脚本、校验器和凭据来源。
6. 初始化状态为 `initialized`，不调用付费生成。

### 输出与闸门

- 标准目录存在。
- `CAPABILITY-MAP.md` 可回答“当前阶段看哪些文件、哪个 Skill 负责什么”。
- `project-intake.json` 状态为 `brief_pending`。

## 6. 阶段 1：沟通并锁定 Brief  〔🟡 P1 要内化〕

由 `ad-creative-expert` 主导，先收集事实，再选择内容方向。不要先让编剧自由扩写。

### 6.1 必填信息

- 业务目标与可观察指标。
- 产品、商品事实、证据、未知项和禁说边界。
- 购买者、使用者、实际观看者及其平台语境。
- 地域、时间、场景、文化和必须避免的信号。
- 平台、广告位、画幅、目标成片时长和声音环境。
- 观看承诺、购买理由、CTA 和转化路径。
- 用户已有的故事、人物、商品、图片、视频、音频和授权状态。
- 必须保留、允许修改和绝对禁止的内容。
- 预算、图片/视频单价、首次成本和付费重试上限。
- 视频模型选择：MiniMax-H3、Seedance-2.0，或暂待选择。

### 6.2 创意路线

1. 如果用户已有明确且确认的故事，只做商品事实、传播目标和可制作性诊断，不强制重新提三条路线。
2. 如果只有商品和目标，比较观看体验真正不同的路线；路线差异必须体现在观众期待、推进方式和产品角色。
3. 参考再创作只继承机制、因果和观众奖励，不复制人物、台词、造型、音乐、镜头资产或 IP。
4. 路线通过 `creative-attention.md` 的创意门后，披露预计资源和首次成本，让用户确认。

### 输出与闸门

- `project-intake.json`：用户事实、假设、待确认项、证据和限制。
- `creative-route.json`：选中路线、观看承诺、产品角色、风险、用户确认时间。
- 用户未确认 Brief/路线时，不进入编剧或生成。

## 7. 阶段 2：编剧完善故事与视频脚本  〔🟡 P1 要内化〕

### 7.1 路由

1. 调用 `screenwriting-master`。
2. 每次读取其 `core-methodology.md`。
3. 15-120 秒广告默认按概念超短片路由并读取 `format-ultrashort.md`，依据实际秒数缩小人物、场景和结构复杂度，不降低观看入口、推进和兑现。
4. 纯视觉、感官、幽默或规则内容也要经过编剧，但不强加传统人物冲突。

### 7.2 编剧步骤

```text
破题与核心动作
-> 梗概草稿
-> 人物/关系/规则（按内容需要）
-> 结构与不可丢失节拍
-> 可摄影视听脚本
-> 剧本医生与内部自检
-> 用户确认
```

每一步遵守 `screenwriting-master` 的暂停纪律。台词必须口语化；情绪改写成动作、视线、停顿、呼吸和选择；不得写摄影机无法拍到的心理解释。

### 7.3 交回 ads 的字段

```text
原始文本及版本
最终剧本及版本
核心动作/规则
观看入口、推进、兑现和回扣
人物、关系、场景和时间
逐场不可丢失节拍
对白/旁白说话人和画内外状态
声音动机与必要留白
预计时长
用户确认记录
```

- `story/source.md` 永远保留用户原文。
- `story/screenplay.md` 和 `screenplay.json` 保存确认版本。
- 未经用户确认的剧本不得进入公共资产和分镜阶段。

## 8. 阶段 3：公共资产、视觉语法与分镜设计  〔🔴 P0 必牢记〕

由 `ad-creative-expert` 读取最终剧本并完成生产翻译，不生产最终提示词。

### 8.1 先建立节拍覆盖

每个必需节拍声明需要的交付通道：

- `picture`：画面状态、动作或反应。
- `dialogue`：对白或旁白。
- `action_sound`：同步拟音。
- `ambience`：环境声。
- `transition`：画面或声音衔接。
- `onscreen_text`：后期字幕、品牌、价格或 CTA。

每个通道必须由 Unit 内部 cut 或 `postTask` 恰好认领一次。遗漏和重复都退回；覆盖只证明已分工，不证明素材质量。

### 8.2 提取公共资产

公共资产只包括跨两个以上镜头复用，或一旦漂移就破坏连续性的对象：

- 人物身份母图、固定发型、体型、妆容和服装。
- 固定场景、空间方向、入口、窗户、家具和光源。
- 真实商品保真图、包装、颜色、比例和不可重绘文字。
- 跨镜关键道具及其初始状态。
- 统一画幅、构图原则、镜头质感、基础光色和禁用风格。

一次性小道具、只在单镜出现的状态和无需锁定的背景细节留在镜头契约，不膨胀公共资产库。

### 8.3 粒度规则

1. 从一次剪切到下一次剪切算一个 `Shot`。连续推拉摇移、跟拍或变焦，无剪切时仍是同一个 Shot。
2. 每个 Shot 填一份 A-G，并保留一个主要观看重点、一个连续时空、一个主要动作目标或状态变化。
3. 发生剪切、时空跳转，或必须独立生成/拍摄/剪辑时新建 Shot。
4. 一个 Shot 对应 1 个或多个 `Panel`：简单展示通常 1 格；简单动作通常起点/终点 2 格；有关键转折通常 3 格；复杂调度可更多，但先判断是否拆镜。
5. Panel 是规划状态，不等于付费图片。只把需要锁身份、空间、动作起点或精确终点的 Panel 生成正式关键帧。
6. 一个 Shot 可拆多个 `Unit`；每个 Unit 是一次模型调用并填 H1-H4，尽量只承担一个主要生成难题。
7. Unit 可有多个内部 cut；无法稳定执行时拆 Unit，不得删减原故事。
8. 连续动作可共用边界帧；正常切镜保持身份、空间、动作方向、视线、光色和道具状态连续；设计性转场使用动作、形状、声音、意义或因果连接；有意断裂写明目的。
9. 镜头时长由动作、对白和节拍决定。多个主要转折、时空或运镜导致过载时拆 Shot 或 Unit，不机械设置秒数上限。
10. 不适用字段写“无/不适用”，不得为了填表增加内容。

### 8.4 视觉连续性与节奏

- 驱动在编剧阶段确定：对白、旁白、动作/事件、物件/意象、对比/结构或音乐/节奏；氛围不能单独驱动。
- 转场由内容决定：正常推进、动作匹配和正反打可以硬切；时间、情绪或空间融合可叠化；匹配转场必须写共享依据。
- 运镜要揭示信息、改变关系或跟随动作。表演、物体或环境已经驱动画面时允许稳定静止镜。
- 同一时空保持人物、方向、道具和基础光色；设计性时空或情绪变化可以改变，但要记录原因。
- “慢/闷/PPT”优先检查：全片匀速、单镜内部无变化、沉默无动力、静止但无表演/环境推进、长尾无新信息。
- 情感 / 短视频项目在本阶段即填 §9 全片级 **[R] 节奏与留存自检**并过阈值门；"慢/闷/PPT"的可量化标准(ASL、静默占比、钩子位置、前3s)见 [R] 与 §15.5，不停留在主观判断。

### 输出与闸门

- `visual-grammar.json`、`assets.json`、`production-plan.json`。
- 每个 `shots/shot-SXX/contract.md` 完整填写第 9 节 A-G 和所有 H。
- 运行 `scripts/validate-production-plan.mjs`；未通过不进入生图。
- 用户确认完整分镜后，状态为 `storyboard_confirmed`。

### 全片级 节奏与留存自检 [R]（分镜阶段填,成片前用 §15.5 脚本实测复核）〔含 🔴 P0 节奏门〕

> **先过 [C] 再过 [R]。** 留存病根在**内容层**([C]:每秒有无新事件推进),[R] 管的是**观感节奏卫生**(钩子前置、别匀速、别静默、别拖长、竖屏)。[C] 是因,[R] 是果的一部分;两者都要过,但 [C] 优先——尤其 R2 的 ASL 已降为诊断信号,不得凌驾 [C]。

"节奏慢"是可量化的,不是主观感受。下列阈值取自电影计量学 **ASL(Average Shot Length,平均镜头时长)** 与短视频平台留存标准,作为默认值(用户最新经验值可覆盖):

- 电影 ASL:古典好莱坞(1930-60)8-11s → 当代好莱坞 **2-3s**;实证显示动作/高潮**末段比首段短约 50%**(高潮该加密,不是拖)。
- 平台留存:**前3秒决定完播、完播率决定分发**;首个切点应在 3s 内、**静止镜 >5s 伤留存**、每 **2-3s** 需一次声画变化重置注意力、8-10s 掉档=钩子空头;完播率优先于片长。

情感类 / 短视频(抖音、视频号、Reels 等竖屏流量场)项目进生成前**必须过本门**;院线长片、纯品牌氛围片等非流量场作品可在 R5 标注豁免并写明理由。

**🔴 护栏:节奏门不得凌驾叙事(呼应 §1.1)。** [R] 分两类,性质不同:

- **节奏卫生类(R2 ASL、R3 静默、R5 片长)与叙事无冲突,任何片子都应执行**——砍静音头尾、按动作节点拆段提切频、压时长,纯剪辑即可,不碰故事。
- **钩子 / payoff 位置类(R1 前3s、R4 前置)可能与慢热 / 反转叙事冲突**(如"结尾才揭底"的反转结构):此时**只能回 `screenwriting-master` 在剧本层重构,或在 R5 写明豁免理由**。**严禁靠打乱镜序、提前揭底、把结尾反转搬到开头来凑 R1/R4 指标**——那是毁叙事,不是提节奏。R1 时序(首切/首声 ≤3s)可在不动镜序下靠砍开场静音头达成;R1 的"钩子质量"若与冷开设计冲突,走生成新钩子镜或剧本重构,不打乱因果。

```text
# 节奏与留存自检 [R]

## R1. 前3秒钩子〔🔴 硬门槛〕
开场镜 ID 与"3秒内给的一个视觉 + 一个信息":
第一个切点时间：≤3s
第一句人声 / 字幕 / 利益点出现时间：≤3s（理想 ≤1.5s）
开场是否 logo / 纯氛围 / 近静音冷镜起：是→退回
判定：通过 / 退回

## R2. 剪辑节奏（ASL，诊断信号——非硬门,硬门看 [C]）
计划切点数 / 平均镜头时长 ASL：参考值 ≤3s（对标当代好莱坞 2-3s、平台"每 2-3s 重置"）
　※ ASL 是"每秒有无新信息"的**诊断信号**,不是留存病根:长镜若 [C] 达标（镜内每 ~2.5s 有新事件）即通过,**不因 ASL 大而退回**;仅当 ASL 大**且** [C] 不达标（有停滞窗）才退回。
单个静止 / 无内部变化镜时长：≤5s（硬顶；无推进镜更严,按 C2 ≤2s）
节奏形态：慢开→提速→高潮加密→收束 ✔ / 全程匀速**且无镜内推进**→退回
高潮·高能段：切点**或镜内事件**须加密（≤ 全片 ASL 或事件间隔更短）
各镜计划入点 @时间轴 + 时长表：

## R3. 静默 / 声画牵引预算
近静音（≤-35dB / ≥0.6s）总占比：≤20%
头 3s、尾 20% 是否有 >1.5s 静默块：有→退回
每 2-3s 是否有一次声画变化（人声 / 音效 / BGM 卡点 / 画面切）：无→退回
每段留白是否有表演动机（冷段演出 / 有意留白）：

## R4. 钩子与信息投放位置
最强钩子 / 反转 / 利益点位置：须在前 1/3；严禁埋在片尾
8-10s 处是否有二次钩 / payoff 兑现：
末段每 2-3s 是否有新信息：无→压缩
删末尾 X 秒是否损失核心：否→砍

## R5. 平台适配与片长
画幅 × 平台：竖屏 9:16（抖音 / 短视频默认）/ 横屏须写理由
目标时长：情感 / 带货短片默认 ≤30-35s；更长须用留存兑现，不许注水（完播率优先于片长）
非流量场豁免声明与理由（如有）：
判定：通过 / 退回
```

### 全片级 内容丰满度自检 [C]（剧本阶段定事件储备,分镜阶段逐拍验;成片前用 §15.5 实测）〔🔴 P0 内容门,优先于 [R] 的 ASL〕

**留存病根在内容层,不在剪辑层。** 真正让观众划走的是"这一秒没有新东西、情绪停住了",不是"没切镜头"。快切只是"逼每秒有新信息"的一种手段;**内容丰满,长镜也留得住;内容不丰满,再快切也留不住。** 故 [C] 先过、且优先于 [R] R2 的 ASL——长镜只要 [C] 达标,不因 ASL 大而退回。

"内容丰满"可量化,核心指标是 ASL 的对偶:**不数"切了几次",数"发生了几件事"**。"新事件"=观众能感知的推进:新动作 / 状态突变 / 反应 / 新台词 / 揭示 / 情绪转 / 关系变化 / 悬念递增。

```text
# 内容丰满度自检 [C]

## C1. 事件密度 AEI（平均事件间隔）〔🔴 硬门槛〕
全片"新事件"总数：____ ；目标时长：____ s
AEI = 时长 / 事件数：默认 ≤2.5s（每拍 ~2.5s 至少 1 个新事件）
逐拍新事件清单（由分镜 A/B 字段点算）：

## C2. 无停滞窗〔🔴 硬门槛〕
是否存在任一 ≥2.5s 窗口"零新事件"（画面在动≠在推进：发呆 / 空镜 / 环境空转 / 慢动作凑时长）：有→退回
单个"无推进"镜时长：≤2s，且须写明表演动机（有意冷段 / 呼吸留白）

## C3. 多通道叠加
每拍同时传信息的通道（动作 / 对白 / 表情 / 道具 / 环境 / 声效）：≥2 通道/拍
全靠单通道（站桩念白、纯氛围空镜）的拍 ID：→ 判稀，加通道或删

## C4. 逐拍不可删（增量推进）
每拍写出"相对上一拍推进了什么（增量）"：情节 / 情绪 / 信息 / 关系 / 悬念
写不出增量的拍 ID：→ 注水拍，删或改（删了无损=不该留）

## C5. 事件储备定片长（剧本层）
剧本"事件清单"条数 × ~2.5s ≈ 合理片长；事件不够 → 压时长，禁用空镜 / 慢动作 / 氛围注水拉长（完播率优先于片长）
氛围不能单独驱动（呼应 §8.4 驱动原则）：驱动=对白/旁白/动作事件/物件意象/对比结构/音乐节奏
判定：通过 / 退回
```

### 规则

- 先生成最上游资产：人物身份、场景、真实商品保真层，再生成依赖它们的变体。

- 图片提示词写清资产用途、构图、主体、环境、光色、必须保持、允许变化和禁止项。

- 一个公共资产未通过，只重做该资产或其最小依赖变体，不重做无关资产。

## 11. 阶段 5：逐镜生成并验收关键帧  〔🟡 P1 要内化〕

按 Shot 顺序执行；一个 Shot 的图片未通过，不提交其视频。

1. 读取该 Shot 的 A-G、Panel 和 Unit H2。
2. 判断哪些 Panel 只是规划，哪些必须成为首帧、尾帧或参考图。
3. 读取并核验所需公共资产；任何依赖为 missing/rejected 时停止本镜。
4. 为必要 Panel 写图片提示词并记录作者、版本和 hash。
5. 检查人物身份、空间、动作起点/终点、商品/道具、构图、字幕安全区和与相邻镜的衔接依据。
6. 披露本镜新增图片成本；按用户已确认范围生成。
7. 下载后检查文件、尺寸、解码和 hash，再做视觉检查。
8. 只有当图片能证明 H2 声明的起止状态和连续性时，标记 `shot_images_accepted`。
9. 错误端点先重做图片，不能指望视频提示词修复错误首尾帧。

## 12. 阶段 6：逐生成单元制作视频  〔🔴 P0 必牢记〕

每个 Unit 独立执行以下循环：

```text

-> 选择模型与模式
```

### 12.1 生成前

- 一个 Unit 只承担 H1 声明的主要难题；提示词不能补写剧本或临时增加动作。

### 12.2 生成后

- 先完整解码和播放，再抽取开场、动作转折、状态完成和结尾关键帧。
- 检查动作因果、人物身份、空间方向、商品/道具、文字/水印、穿模、真实时间变化及与前后镜的依据。
- 不通过时记录偏差和最小重做范围；不自动付费重试。

## 13. 模型与提示词路由  〔🟡 P1 要内化〕

### 13.1 模型选择

- 项目必须在 `prompt-policy.json` 显式锁定视频模型。未选择时状态为 `model_selection_pending`，可以做 Brief、剧本和分镜，但不能写正式生产提示词或付费生成。
- MiniMax-H3 使用 `h3-prompt-writing`；Seedance-2.0 使用 `seedance-prompt-zh`。
- 模型切换时冻结新提交，重写受影响提示词，重新核对素材、模式、时长和 provider，重新审查 hash 并重算成本。旧素材保留原模型和证据。

### 13.2 MiniMax-H3

|模式|使用条件|
|---|---|
|T2VA|无关键帧，从文字构建完整时间线|
|I2VA|只有首帧，动作自然向后发展且无需精确终点|
|FL2VA|需要锁定首尾状态并描述连续路径，通常优先单镜|
|L2VA|只有尾帧，需要从合理前态逐步收敛|
|Ref2VA|参考视频、图片或音频提供完整结构、延续或编辑关系|

- 使用 H3 规定的英文结构、字段顺序、时间标记和 `<Picture N>` 等标签。
- H3 v2 首尾图片必须明确为 `first_frame` 或 `last_frame`，不能用模糊 `reference_image` 代替。
- `integrated_multimodal_description` 负责视觉、动作、镜头、对白和画内声音；另写 `overall_soundscape` 与 `non_diegetic_music`。

#### 13.2.1 H3 对白字幕:H3 只出配音,字幕后期统一烧  〔🔴 P0 必牢记〕

H3 对含 `<d>…</d>` 对白的镜头会**非确定性地把台词烧成硬字幕**：同一提示词有时烧、有时不烧，字体/位置/大小不可控；即使提示词写满 anti-subtitle 约束（no subtitles / captions / on-screen text / Chinese characters / watermark）也**不能保证**不烧。

H3 对含 `<d>…</d>` 对白的镜头会**非确定性地把台词烧成硬字幕**:同一批里有时烧、有时不烧,字体/位置/大小不可控(实测《小猪起床了》fastwake v2 三条只 1 条烧)。**同片内字幕时有时无 = 观感不一致,不能做成品。**

**默认标准(用户 2026-09-16 定,取代 2026-09-14 的"直出即成品")**:
- **H3 只负责对白配音 + 完整表演**;字幕**一律由后期统一烧录**,不依赖、不采信 H3 直出的字幕。
- 提示词侧:对白镜显式加 anti-subtitle 约束(no subtitles / captions / on-screen text / Chinese characters / watermark),尽量让 H3 出**干净画面(只配音不烧字)**;但这是 best-effort,H3 仍可能烧 → 生成后**必须逐条 QC 确认无残留硬字幕**。某条若仍烧:优先弃尾/裁剪避开;避不开则该条重生成(个案),**绝不在已烧像素上再叠一层后期字幕**(会双字)。

**提前为后期烧录做的准备(分镜/关键帧/提示词阶段就位,把字幕当一等公民)**:
1. **字幕清单结构化(subtitle manifest)**:分镜 E声音 字段的台词升级为可导出清单——每项 `{clip, speaker(S1/S2), text, t_start, t_end}`;这是后期烧录的**唯一字幕源**,不事后重听转写。
2. **时间轴换算**:manifest 用**片内相对时间**;因每条弃尾只取 0–5.0s、拼接后第 i 条偏移 (i-1)×5s,烧录脚本按"裁剪+拼接"换算成全片时间轴。逐句要精确可听音/ASR 微调,默认用分镜规划窗口。
3. **字幕安全区**:关键帧文生图与分镜 C画面 约束**底部 ~15–18% 留干净安全区**(不放关键动作/人脸/重要道具/品牌字),避免字幕压盖。
4. **统一样式(可复用 ASS)**:思源黑体/Noto Sans CJK SC、底部居中、白字+细黑描边(或半透明底)、约画面 88% 高、一拍一行、每行 ≤~15 字;定义成一份复用样式,全项目统一。样式与字体路径见 `replication/tools/burn-subtitles.sh`。
5. **字体可用性**:烧录环境须装中文字体(本机已装 `/usr/share/fonts/opentype/noto/` Noto CJK);ffmpeg `subtitles` 走 fontconfig 或 `fontsdir`/`force_style` 指定,提前验证不回退成方块。
6. **工具化 + 阶段固化**:字幕烧录是**确定性剪辑的固定阶段**(呼应 §14 SKILL.md 第 2 条)。流水线:生成→逐条 QC(无残留字幕)→弃尾裁剪→拼接→**统一烧字幕(`burn-subtitles.sh`)**→混音/loudnorm→编码→验收。
7. **双 QC 门**:①生成后——每对白镜确认"中文配音在 + H3 无残留硬字幕 + 表演完整";②后期烧录后——每拍字幕在、与语音同步、样式一致、无双字。无对白冷段不烧。

- **不要事后抠字幕**:字幕烧进像素后去除=有损修复(delogo/inpaint),留糊块色差;所以用 anti-subtitle + QC 拦在前,不在后端抠。
- **禁止用"删对白改无声"来规避**:那是回避问题不是解决问题——会丢台词与表演。
- 参见记忆 `subtitle-post-burn-standard`(取代旧的 `h3-dialogue-native-subtitle-is-standard`)与 `h3-dialogue-burns-subtitles-nondeterministic`。

### 13.3 Seedance-2.0

- 使用 `@图片N`、`@视频N`、`@音频N`，每项明确职责；不得只写“参考”。
- 图片不超过 9、视频不超过 3、音频不超过 3，总文件不超过 12；视频/音频时长和写实真人脸限制以当前 Skill 与账号版本为准。
- 输出 4-15 秒；长于 8-10 秒或动作较多时使用分时段描述。
- 消除“固定镜头/环绕镜头”等冲突；素材无归属、内容过载、时长不匹配时退回。

### 13.4 模式不是项目统一模板

同一项目内逐 Unit 判断：自然发展用 I2VA，严格起止用 FL2VA，只有身份/场景/风格一致时用参考模式。Panel 数量不决定模式，只有控制需求决定是否生成关键帧。

## 14. 成本、付费与防重复提交  〔🔴 P0 必牢记〕

### 14.1 成本

```text
首次成本 = 新图片数 x 图片单价 + 新视频秒数 x 视频每秒单价
最坏累计 = 首次成本 + 已披露重试预留
```

- 当前默认图片 0.25 元/张、视频 0.2 元/秒；用户最新报价覆盖默认值。
- 已有素材不计生成费，但必须验收。
- 成本按公共资产、Shot、Unit 和全片四层汇总。
- 失败生成也计费；不得隐藏失败或把重试并入“免费修正”。

### 14.2 付费闸门

首次付费前必须存在 `automation/preflight.md/json` 和 `cost-plan.json`，记录素材、缺口、输入 hash、引用职责、连续性、可拍性、提示词容量、运镜冲突、文字禁令、模型模式和预算。

任何 `fail`、`unknown`、未验收依赖、未通过提示词审查或 hash 失配，都令 `generation_allowed=false`。

### 14.3 事务状态

```text
ready -> submitting -> generated_pending_qc -> accepted / rejected
```

- 使用单一状态文件、资产级幂等 ID、进程锁、原子写入和不可覆盖输出。
- 提交前创建永久 `submission.locked`，保存提示词、请求、响应、生命周期和 SHA-256。
- `submitting`、`ambiguous_submission` 或 `generated_pending_qc` 存在时关闭全局付费闸门。
- POST 后网络错误进入 `ambiguous_submission`，先查询供应商任务，禁止自动重提。

## 15. 技术、视觉、语义与连续性验收  〔🔴 P0 必牢记〕

### 15.1 图片

- 文件存在、格式/尺寸/解码正确、hash 已记录。
- 人物身份、年龄、脸、发型、体型、服装与公共母图一致。
- 场景方向、光源、道具数量和位置符合契约。
- 动作起点或终点能被静态画面验证。
- 商品真实、无结构漂移；模型乱码、未授权标识和水印不存在。
- 与前后镜的连续性依据可核对。

### 15.2 视频技术 QC

- 用 `ffprobe` 检查路径、时长、分辨率、帧率、编解码和音频。
- 用 `ffmpeg` 完整解码；不能只看缩略图或状态 JSON。
- 保存开场、转折、完成和结尾抽帧，但抽帧不能替代完整播放与听审。

### 15.3 视频视觉与语义 QC

- H1 声明的主要动作完整、因果清楚，没有新增或丢失节拍。
- 人物、空间、视线、运动方向、商品和道具前后一致。
- 手、脸、衣料、商品和交互无明显穿模或畸变。
- 主要镜头存在真实时间变化，不是静态图片缩放形成的伪视频。
- 前后镜满足分镜契约声明的连续状态、匹配转场或有意断裂。
- 无法视觉检查时只能标记 `not_accepted`，不能声称通过。

### 15.4 最小失败分类

|失败|只回到|
|---|---|
|故事或节拍遗漏|编剧/分镜|
|人物、场景、商品母图错误|对应公共资产|
|首尾状态错误|对应关键帧|
|单段动作、手部或时序错误|对应 Unit 视频|
|字幕、旁白、拟音、混音或编码|后期任务|
|模型模式错误|该 Unit 的 H2/H3|

### 15.5 成片前节奏与留存实测门〔🔴 P0〕

情感 / 短视频成片进入 `final` 前，除 15.1-15.3 外必须用脚本量化复核 §9 的 **[C] 与 [R]**，不靠眼估：

- **[C] 内容层(优先)**:逐拍核对"新事件"落点(动作 / 状态突变 / 反应 / 台词 / 揭示)→ 事件密度 AEI ≤2.5s、有无 ≥2.5s 停滞窗(画面动但无推进);抽帧+听音复核每拍都在推进。长镜尤其要查**镜内是否持续有新事件**——达标则 ASL 大也通过。
- `ffmpeg -af silencedetect=noise=-35dB:d=0.6` → 近静音总占比(阈值 ≤20%)、头 3s 与尾 20% 是否有 >1.5s 静默块。
- 由各镜入点 / 时长算切点序列 → **ASL 均值**(诊断参考 ≤3s,非硬门)、是否全程匀速**且无镜内推进**、高潮段是否加密、有无 >5s 静止镜。
- 用 `ffprobe` 标出第一个切点、第一句人声、最强钩子的时间戳 → 钩子是否 ≤3s、强钩子是否在前 1/3。
- 画幅 × 平台核对(竖屏 9:16 等)。

任一项越阈值 → `not_accepted`，退回**剪辑**(重排 / 拆段提切频 / 砍尾 / 补前3s钩子)或退回**分镜**([R] 重填);越阈值不得标记 accepted。豁免须在 [R] R5 写明理由。反例见 §19.4《小猪起床了》。

## 16. 暂缓的最终成片阶段  〔🟡 P1 要内化〕

用户尚未确认最终成片的具体制作方式，因此当前流程在所有 Unit 视频 accepted 后停在 `final_workflow_pending`。此时必须交付：

- 全部 accepted/missing/rejected 素材清单。
- 每个 Unit 的建议入点、出点和目标时长。
- 分镜原定硬切、叠化、匹配转场或声音桥。
- 对白、旁白、环境、拟音、BGM 分轨需求。
- 后期字幕、品牌、CTA、安全区和真实商品落版任务。
- 目标画幅、帧率、编码和平台限制。
- 未解决问题和待用户决定项。

在最终方案确认前：

- 不把镜头素材合集称为成片。
- 不使用系统 TTS 进入最终文件。
- 不因素材缺失改写原故事或用静态推拉补洞。
- 不标记项目 `complete`。

## 19. 案例参考:《小猪起床了》情感短片(H3 · 关键帧锚定)  〔⚪ P2 用到再查〕

**详细内容即产物,不在本文件展开,顺链去看**:分镜逐镜 A–G/衔接 `replication/output/xiaozhu-qichuang-20260914/review/storyboard.md`;契约 `…/contracts/*.json`;剧本原文 `…/story/screenplay.md`;声音配方 `…/edit/build-final-cut-v1.sh`。下面只留可复用要点。

### 19.1 剧本 → 分镜的一致性(靠派生 + 校验,不靠人肉记)

- 每个分镜的 **A 故事与节拍**回引原文台词/画面("对应原文『…』")并认领一个**命名节拍 B1..Bn**;`validate-production-plan` 校验**每个节拍恰好被认领一次**、不新增不丢——分镜严格从确认剧本派生且可核验一致。
- 提示词阶段**不得补写剧本或加动作**(见 12.1);要改剧情回编剧,不在分镜/提示词层"顺手加戏"。剧本 `story/screenplay.md` 不可覆盖。
- 怎么落地看 `review/storyboard.md` 各镜 **A** 字段与第五节"全片提交检查"。

### 19.2 分镜才是连贯的保证——必须严格填空,不是 PPT

- **连贯不来自单镜好看,来自分镜把镜与镜的因果串死**。逐镜严格填 A–G,重中之重是 **D 镜间衔接**:写死"承接上镜哪个状态 + 为下镜留哪个状态 + 验证依据",相邻镜靠 match cut / 状态承接接上(本项目每条 D 都是"承接 S0x;为 S0(x+1) 留…")。**没有 D 衔接依据的镜不许进生成。**
- **是否严格执行 = 看提交检查勾没勾**:本项目"相邻镜有连续性依据""9 个节拍各认领一次"均已勾(`review/storyboard.md` 第五节)。填空是硬门槛,不是走形式。
- 把独立漂亮镜头排在一起 = 幻灯片/PPT,是前几版不连贯的根因;**拆多机位 + 正反打剪到一起**才连贯(记忆 `coverage-continuity-editing-vs-slideshow`、`ai-live-action-no-slideshow-sop`)。
- 模式随镜定、不套统一模板:状态突变动作用 FL2VA(本项目 S05–S08 拽人/亲抱举/爬背/背起),自然发展用 I2VA(其余);逐镜模式见 `review/storyboard.md` 各镜标题(记忆 `fl2va-for-state-change-actions`、`shot-language-by-scene-not-uniform`)。

### 19.3 声音初剪(可复用配方,脚本即文档)

对白镜"测量 `loudnorm` 的 input_i/tp → `volume=XdB` 线性平移到 -18 LUFS、TP≤-1.5",不压缩;**别用 loudnorm 两遍**(高 LRA 近静音带单句的镜会崩到 -28 或反弹到 -8);冷段近静音不归一不抬噪;视频 `-c:v copy` + 音频统一 aac 后 `concat`。参数与实现见 `edit/build-final-cut-v1.sh`。

### 19.4 踩坑与纠偏

- **节奏被判"慢"是可量化的四硬伤(本片反例,已立 §9 [R] 门 + §15.5 实测门防再犯)**:①前 5.78s 无声冷开、第一句人声才 5.78s 出(3s 跳出杀手,违 R1);②切点匀速 ASL 5.26s、且高能段 S05/S06 达 6.58s=全片最慢(高潮反而拖,违 R2);③近静音占 ~33%、头尾各一大块(违 R3);④最强钩子"手机·一年前的今天"埋在 48s/91% 处(违 R4);外加横屏 16:9 投竖屏场、52.6s 偏长(违 R5)。这些与"单镜好不好看"无关,是结构编排问题;参见记忆 `pacing-slowness-retention-gate`。
- **[R] 门实测验证(零生成剪辑测试,不动 final)**:保持原叙事顺序、只做节奏卫生(砍静音 + 按动作节点拆段 + 压时长),把 R2(ASL 5.26→2.17s)、R3(33%→15.5%)、片长(52.6→21.9s)、R1 时序全部翻成通过,证明门抓得准、卫生类照做即生效。**但 R4(强钩前置)与本片"结尾揭一年前的今天"的反转结构真冲突**:一度为凑 R4 把暖峰重排到开头,直接毁掉叙事因果——这验证了 [R] 护栏"节奏门不得凌驾叙事":R1/R4 与慢热/反转冲突时回编剧或走豁免,严禁打乱镜序凑指标。
- H3 对白镜只出中文配音+表演,字幕**后期统一烧**(不采信 H3 直出字幕,同片内烧字不一致);分镜阶段备好字幕清单/安全区/样式(见 13.2.1)。本项目 S04 曾按旧标准直出字幕,现改后期统一烧。
- **单条提示词塞两次内部硬切不可靠**:S04 正反打第二次"切回男"被非确定性丢掉;要稳就用直出能一次成的那条,或拆机位分别生成再剪。
- 验"字幕/对白/正反打达标"看素材本身(抽帧 + 封装签名:H3 直出 `Lavf58.29.100` vs 本地 ffmpeg 盖不同 Lavf),不能只看状态 JSON。
- 媒体不入库,仓库只提交文本(记忆 `no-media-in-repo`)。
